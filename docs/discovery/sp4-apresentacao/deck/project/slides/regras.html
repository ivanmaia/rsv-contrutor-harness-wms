Três regras que não se quebram

1

Nunca rode git push para os repos nem git subtree à mão: quem envia é o ws push.

2

Dentro de repos/<repo>/, não crie nem altere .specify/, specs/ e .claude/skills/speckit-*.

3

Durante uma feature, não altere o harness. Achou um problema nele? Registre para o time do harness.

Harness WMS · 17/29

As regras vêm da camada 1. A primeira: o envio passa pelo ws push, que sabe separar as mudanças de cada repo. A segunda: esses arquivos são do time dono do repo, e o ws push recusa a branch se eles mudarem. A terceira: o harness é tools, .specify, .claude e AGENTS.md; mudanças nele vão numa branch própria. Tempo: 1,5 min
