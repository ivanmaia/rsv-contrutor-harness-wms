2

4

/speckit-bug-test

Build e testes de verdade. No fim, atualiza o Atlas e oferece o commit e o envio.

SEM CORREÇÃO DE CÓDIGO

Não é bug, ou a correção é no dado ou na infraestrutura: o agente registra o relatório e você abre só o PR do workspace.

Harness WMS · 18/28

Para um bug reportado num work item ou um erro em produção; um erro que aparece durante uma feature fica no fluxo da feature. No assess, cole o relato com o id do work item, se houver, e as evidências: stack trace, log, print, resultado de consulta. O slug é o id do work item mais uma descrição curta; sem work item, inc- com a data. O agente investiga só lendo: o código, o Atlas e, se você tiver acesso, consultas SELECT que ele mostra antes de rodar. Se a correção muda um contrato, o diagnóstico lista os consumidores afetados, pelo índice de impacto do Atlas. O test só diz verified se conferiu de fato. Os PRs seguem como na feature: um por repo e, com todos mergeados, o do workspace. Um incidente que só precisa ser entendido usa o mesmo assess e termina no registro. Tempo: 2,5 min
