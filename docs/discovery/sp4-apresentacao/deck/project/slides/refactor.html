3

/speckit-refactor-apply

Primeiro os testes que fixam o comportamento atual, num commit próprio. Depois, o refactor.

4

/speckit-refactor-verify

Build, testes e a conferência de que os testes de caracterização não mudaram. Depois, Atlas e envio.

A REGRA

O comportamento observável não muda. Mover código entre repos e migrar para o AWX ainda não entram aqui.

Harness WMS · 19/29

Refactor é mudar a estrutura sem mudar o que o código faz; é a regra VII da constitution. O teste de caracterização chama o código como ele está e afirma o que ele devolve hoje, mesmo que pareça estranho: o objetivo é fixar, não corrigir. A exceção serve só para trecho que não dá para testar sem um refactor anterior, como uma tela WebForms com acesso ao banco, e precisa da sua aprovação. Os testes que já falhavam antes do refactor ficam registrados e não barram; uma falha nova barra. Se o diagnóstico concluir que a mudança altera comportamento, o veredito é reclassificar: vira feature ou bug. Tempo: 2,5 min
