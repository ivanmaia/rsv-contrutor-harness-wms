Harness WMS · 21/63

É a novidade do SP7: os PRs saem pelo harness. A oferta vem sozinha no fim do /ws-commit-push. O agente mostra o plano com ws pr plano homolog: um PR por repo enviado mais o do workspace. Pergunta se abre e pede o número do card do Azure Boards (ou sem card); nunca inventa. Com o sim, roda ws pr abrir homolog --card n: envia a branch do workspace ao origin, abre os PRs das subtrees e depois o do workspace, com a tabela dos PRs das subtrees, atualiza as descrições, posta no espaço de homologação do Google Chat e mostra os links. Com o não, mostra os links pullrequestcreate para abrir à mão. Rodar de novo não duplica PR: só atualiza a descrição. Se a entrega não muda nenhum repo, o harness oferece só o PR do workspace direto para o main. Atenção: enquanto um repo tocado não tiver o ramo homolog no origin, o ws pr não abre nenhum PR da entrega. Sete repos estavam sem homolog em 21/10: print-zebra.utilitario.backend, wms.app.frontend, wms.hubprodutividade.backend, wms.servidor.backend, wms.tms-finished.backend, wms.tms.backend e wms.trakta.backend (não conferi hoje). No PR de subtree para o ramo de teste há o aviso para não apagar a branch de origem. Ainda não foi validado no real o ws pr abrir main e a recriação de branch apagada. Tempo: 2 min
