Harness WMS · 60/63

O ws é o script do workspace: roda como tools/ws/ws seguido do comando, no Git Bash, na raiz. No fluxo normal você chama quase nenhum: o ws start vem pelos hooks de início, e o ws push e o ws pr plano e abrir vêm pelo envio no fim e pelo /ws-pr-main. O ws sync atualiza uma branch parada: rode tools/ws/ws sync e depois git merge --no-edit ws/sync; se o sync falhar, ele volta para a sua branch sem trazer nada (o ws start também). O ws pr revisao e o ws pr comentar são chamados pelo /ws-pr-review. O ws refactor fatia pendentes lista as fatias de desacoplamento, e status mostra uma fatia. Ficaram fora do slide os ws atlas, add, maintain e speckit: são chamados pelas skills do Atlas e pelos hooks, ou usados por quem mantém o harness; à mão, só para diagnóstico. A exceção é o ws atlas mapas na instalação das ferramentas do Atlas. Tempo: 1 min
