Harness WMS · 54/63

Como funcionou no piloto: o observador anota cada travada com a etapa e as palavras do dev; o dev procura primeiro na camada 2 da doc; cada linha com ação vira um PR de acompanhamento no workspace. Exemplos reais: sistema fora do workspace virou a regra 7 do AGENTS.md e entrada na camada 2 (PR 17070); caminhos longos fora do git viraram o passo 2 da camada 1 (PR 17070); ws push caindo no HTTP/2 do Azure DevOps passou a usar HTTP/1.1 e buffer de 500 MB (PR 17072); o Atlas do Linx apagado no início da feature foi corrigido (PR 17073); avisos do ws start que não chegavam ao dev (PR 17103). Mais recentes, de 21 e 22/10: ws push parava com "fatal: cache for <sha> already exists!" por marcador de split repetido, e agora usa a cópia tools/ws/vendor/git-subtree-ws (Git 2.54.0 com cache_set tolerante); ws sync e ws start deixavam a árvore na ws/sync quando a rede falhava, e agora voltam para a branch (PR 17254; ADR 0001, adendo 7). O recado: o que vocês registram vira correção. Tempo: 1,5 min
