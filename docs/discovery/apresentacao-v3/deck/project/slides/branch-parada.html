Feature que muda ou branch parada

Feature que muda

  • Rode /speckit-specify citando o número da feature (a 004, ws-004) ou o nome da pasta.
  • O hook cria a branch ws-NNN-<nome>-r<k> e edita a spec existente.
  • É a living spec: a revisão fica na mesma spec.
  • Feature ainda não mergeada: fique na branch dela.

Branch parada

  • Árvore limpa, então tools/ws/ws sync e depois git merge --no-edit ws/sync.
  • Nunca use rebase nem merge do origin/main.
  • Se o sync falhar, ele volta para a sua branch, sem trazer nada.

Harness WMS · 27/63

Duas situações comuns depois da primeira entrega. Mudar uma feature que já existe: rode o /speckit-specify citando o número ou o nome da pasta; o hook cria a branch com o sufixo r e o número da revisão e edita a spec existente, que registra a revisão. Se a feature ainda não foi mergeada, fique na branch dela. Branch parada que precisa do que entrou no main: com a árvore limpa, rode tools/ws/ws sync e depois git merge --no-edit ws/sync. Nunca faça rebase nem git merge origin/main. Se o ws sync falhar, por exemplo por rede, ele volta para a sua branch sem trazer nada; rode de novo. Se aparecer conflito no sync de um repo, peça ajuda ao time do harness. Tempo: 1 min
