A spec em linguagem de negócio. A seção Repos afetados lista os repos certos?

Harness WMS · 13/63

Você descreve a feature como pediria a um colega. O hook do Spec Kit deriva um nome curto, acha até cinco repos prováveis pelo Atlas, roda o ws start (sincroniza a ws/sync com o main de cada repo, envia a ws/sync e cria a branch ws-NNN-nome a partir dela), atualiza o Atlas dos repos que mudaram e cria a spec. Não crie a branch nem a pasta da spec à mão. O que você confere: a spec em linguagem de negócio e a seção Repos afetados, que é obrigatória. Se a spec cita um sistema fora do workspace, o agente oferece seguir com ele como externo ou parar e pedir a inclusão; escolha uma das duas e não indique a pasta ao agente. O hook pode avisar na resposta o link do PR da ws/sync ou que o main local está à frente. Se o hook parar, nenhuma spec é criada: a camada 2 da documentação explica cada erro. No primeiro uso o specify pode passar de 20 minutos por causa do Atlas. Tempo: 2 min
