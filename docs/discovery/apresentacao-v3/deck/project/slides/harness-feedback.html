Como melhorar o harness

Durante uma feature

O agente propôs mexer em tools/, .specify/, .claude/ ou AGENTS.md? Recuse e registre o problema. A correção sai fora da feature.

Onde registrar

Thread no espaço Equipe WMS do Google Chat. Mande o comando, a mensagem completa e a saída de:

git status
git log --oneline -3

Segredo nos docs do Atlas: registre só o nome do repo, sem colar o trecho.

Harness WMS · 53/63

Regra de ouro: durante uma feature, um bug ou um refactor, não se muda o harness. Todos os comandos speckit.ws.* e a ws-pr-review repetem: descreva o problema e sugira registrá-lo para o time do harness. O canal é a thread de suporte do espaço Equipe WMS (https://chat.google.com/room/AAAAKpyvLWs?cls=7). Mande o comando ou skill que rodou, a mensagem completa e a saída de git status e git log --oneline -3; isso poupa a primeira rodada de perguntas. Sobre segredos: se aparecer um nos docs do Atlas, registre só o nome do repo, sem colar o trecho. Pedidos que só o time do harness resolve: incluir um repo no workspace, conflito no sync de um repo, política na ws/sync (TF402455) e mudar o ramo de teste de um repo no workspace.pr.ini. Tempo: 1,5 min
