Um bug, do relato ao PR

1

/speckit-bug-assess

Cria a branch hotfix/<slug> e grava o diagnóstico em bugs/<slug>/. Só leitura; não muda código.

2

Leia o assessment.md

Só siga se concordar com a causa e a correção. Se mudar contrato, confira a seção Impacto.

3

/speckit-bug-fix

Aplica a correção e grava o fix.md.

4

/speckit-bug-test

Build e testes de verdade: verified, partial ou failed.

SEM CORREÇÃO DE CÓDIGO

Não é bug, ou a correção é no dado ou na infraestrutura: o agente registra o relatório e oferece o PR do workspace direto para o main, sem homologação.

COM CORREÇÃO

No fim: Atlas, commit e envio. Depois, a mesma oferta dos PRs da feature, passos 9 a 11.

Harness WMS · 33/63

Para um bug reportado num work item ou um erro em produção; um erro que aparece durante uma feature fica no fluxo da feature. No assess, cole o relato com o id do work item, se houver, e as evidências: stack trace, log, print, resultado de consulta. O slug é o id do work item mais uma descrição curta, ou inc- com a data. O agente investiga só lendo: código, Atlas e, se você tiver acesso, consultas SELECT que ele mostra antes de rodar; sem acesso, ele escreve a consulta para você rodar. Valores sensíveis não vão para os relatórios. Se a correção muda um contrato, o assessment tem a seção Impacto. Sem correção de código, o agente oferece o PR do workspace direto para o main (ws pr abrir main), sem homologação. Com correção, é a mesma oferta dos PRs da feature: ramo de teste, depois promover, depois completar com o workspace por último. Investigar sem corrigir: mesmo assess, slug inc-, termina no registro em bugs/. Nota: o ws pr abrir main e a recriação de branch apagada ainda não foram validados no real. Tempo: 2 min
