Revisar um PR com o harness

/ws-pr-review <link do PR do workspace>

QUEM

O colega revisor.

ONDE

No workspace dele, dentro do Claude Code.

O QUE VÊ

O workspace e todas as subtrees juntos, pelo diff contra a base da ws/sync.

O link do navegador com ?_a=overview serve. O PR precisa ter sido aberto pelo harness.

Harness WMS · 38/63

A revisão é feita pelo colega revisor, no workspace dele, com /ws-pr-review e o link do PR do workspace (.../_git/repo/pullrequest/id). O comando tools/ws/ws pr revisao busca a branch do PR num worktree e grava .ws/revisao/id/contexto.json com o diff do workspace e o de cada subtree contra a base da ws/sync, não contra o destino, para não trazer código de outras pessoas. As fontes são a origem (spec.md e tasks.md, ou assessment.md, ou rollout-plan.md), a constitution, o AGENTS.md e o docs/convencoes.md de cada repo da entrega. Só revisa PR do workspace aberto pelo harness, o que tem a tabela das subtrees; se vier outro, o erro é "o PR não tem a tabela das subtrees". O par a revisar é o de homolog, que nasce primeiro; o de main sai da mesma branch. Observação para o time do harness: o passo de leitura não cita CLAUDE.md, copilot-instructions nem .claude/rules, onde estão as regras do Fly. Tempo: 1,5 min
