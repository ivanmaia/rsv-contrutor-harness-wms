# Sincronização pela branch `ws/sync` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** o `ws start` deixa de fazer push no `main` do workspace: a sincronização dos repos vai para a branch compartilhada `ws/sync`, enviada só com fast-forward e levada ao `main` por PR.

**Architecture:** a base do `ws` (`WS_BASE`) passa de `main` para `ws/sync`, e o destino dos PRs vira `WS_DESTINO=main`. Toda leitura da base passa por `ws_base_ref`, que cai para `origin/ws/sync` e depois para o `main` quando a `ws/sync` local não existe. O `ws start` vira `ws sync` (prepara, sincroniza, envia, avisa) mais a criação da branch.

**Tech Stack:** bash (Git Bash no Windows), git com git-subtree, Python 3 (`tools/atlas/plano.py`), testes em bash (`tools/ws/tests/run.sh`).

**Spec:** `docs/superpowers/specs/2026-10-15-ws-sync-design.md` (pasta de discovery `C:\src\00-harness_big_brown_field`). O código fica no workspace `C:\src\wms-workspace`.

## Global Constraints

- Tudo em pt-BR: mensagens, comentários, docs e commits.
- Commits no workspace com o prefixo `harness: ` e sem atribuição ao Claude.
- Branch de trabalho: `harness/ws-sync`, criada a partir do `main` atualizado do workspace (`git switch main && git pull --ff-only origin main && git switch -c harness/ws-sync`).
- Nunca fazer push no origin do workspace: o usuário envia a branch e abre o PR.
- `WS_BASE=${WS_BASE:-ws/sync}` e `WS_DESTINO=${WS_DESTINO:-main}`.
- O push da `ws/sync` é sempre fast-forward, nunca forçado.
- Até 3 tentativas de envio no `ws sync` (`WS_SYNC_TENTATIVAS`, padrão 3).
- Mensagens exatas (spec, seção 5.3):
  - `push de ws/sync recusado por política do Azure DevOps (TF402455); a ws/sync não pode ter política de PR. Peça ao time do harness. Nada foi alterado no main.`
  - `push de ws/sync recusado 3 vezes; rode o comando de novo. Resposta do origin: <resposta>`
  - `push de ws/sync recusado. Resposta do origin: <resposta>`
- O aviso de idade do PR da `ws/sync` usa `pr_max_dias` do `tools/atlas/relevancia.ini` (hoje 7).
- Rodar um teste: `cd /c/src/wms-workspace && WS_TEST=<nome> bash tools/ws/tests/run.sh tools/ws/tests/<arquivo>.sh`. Suíte inteira: `bash tools/ws/tests/run.sh` (leva cerca de 25 min; rodar num worktree temporário, como em `git -c core.longpaths=true worktree add --detach <scratch>/wt HEAD`).
- A extensão `ws` do Spec Kit tem duas cópias que precisam ficar iguais: `tools/speckit/ws/` (fonte) e `.specify/extensions/ws/` (instalada). Depois de mudar uma, copiar para a outra e conferir com `diff -r tools/speckit/ws .specify/extensions/ws` (a única diferença aceita é `Only in .specify/extensions/ws: .specify-dev`).

## Review Focus

- **Branch aberta antes da mudança (a do piloto) sem `ws/sync` local:** `ws push`, converge e `ws-bug-registro.sh` precisam cair para o `main` e enxergar só a feature (Task 1, teste de `ws_base_ref`; Task 3, teste 7).
- **Conflito no sync de um repo:** a mensagem precisa mandar enviar a `ws/sync` resolvida, porque o `ws sync` seguinte reposiciona a `ws/sync` local na do origin e jogaria fora a resolução não enviada (Task 2, teste de conflito).
- **`main` local à frente do origin (o caso do relato):** nada pode ser apagado, e o aviso precisa dizer o comando (Task 2, teste 6).
- **Rede falhando ao ler o origin:** não pode ser confundida com "a `ws/sync` não existe", senão o `ws sync` recria a `ws/sync` a partir do `main` (Task 2, teste de `ls-remote` com falha).
- **Feature que traz o `main` depois de um repo novo:** com `ws sync` e `git merge ws/sync`, o `ws push` não envia o subtree inteiro do repo novo (Task 3, teste 10).

- [ ] **Step 4: Reescrever `tools/ws/lib/start.sh`**

Conteúdo completo:

```bash
# ws sync e ws start: sincronizam os repos na branch base (ws/sync), enviam a base ao origin só com
# fast-forward e, no start, criam a branch a partir dela (ADR 0001, adendo 6). O main do workspace
# só muda por PR: nada aqui faz push nele.

WS_SYNC_TENTATIVAS=${WS_SYNC_TENTATIVAS:-3}
WS_SYNC_ERRO=""

# ref -> traz a ref (o destino) para a base atual: fast-forward quando dá, merge quando não. Um
# conflito aqui não deveria acontecer (os dois lados compartilham a linha de sincronização): aborta
# e para, sem enviar nada.
ws_sync_traz() {
  local ref=$1
  git merge-base --is-ancestor "$ref" HEAD && return 0
  if ! git merge -q --no-edit -m "ws: traz o $WS_DESTINO para a $WS_BASE" "$ref" >/dev/null 2>&1; then
    git merge --abort 2>/dev/null || true
    die "conflito ao trazer o $WS_DESTINO para a $WS_BASE; nada foi enviado. Peça ao time do harness"
  fi
}

# Deixa a base local igual à do origin (ou, se ela ainda não existe lá, ao destino do origin) e traz
# o destino para dentro dela. Sem origin, parte da base local ou do destino local.
ws_sync_prepara() {
  local inicio rc
  if has_origin; then
    git fetch -q origin "+refs/heads/$WS_DESTINO:refs/remotes/origin/$WS_DESTINO" 2>/dev/null \
      || die "não consegui buscar o $WS_DESTINO do origin: verifique a rede e a credencial"
    if git ls-remote --exit-code --heads origin "$WS_BASE" >/dev/null 2>&1; then
      git fetch -q origin "+refs/heads/$WS_BASE:refs/remotes/origin/$WS_BASE" \
        || die "não consegui buscar a $WS_BASE do origin: verifique a rede e a credencial"
      inicio="origin/$WS_BASE"
    else
      rc=$?
      [ "$rc" -eq 2 ] || die "não consegui ler o origin: verifique a rede e a credencial"
      git update-ref -d "refs/remotes/origin/$WS_BASE" 2>/dev/null || true
      inicio="origin/$WS_DESTINO"
    fi
    git checkout -q -B "$WS_BASE" "$inicio"
    ws_sync_traz "origin/$WS_DESTINO"
  else
    if git show-ref --verify -q "refs/heads/$WS_BASE"; then
      git checkout -q "$WS_BASE"
    else
      git checkout -q -b "$WS_BASE" "$WS_DESTINO"
    fi
    ws_sync_traz "$WS_DESTINO"
  fi
}

# rotulo -> sincroniza na base os repos que mudaram no remoto e grava os marcadores de rejoin.
# O rótulo entra na mensagem de conflito ("ws start <branch>" ou "ws sync").
ws_sync_repos() {
  local rotulo=$1 heads prefix url remote cur changed=""
  heads=$(ws_remote_heads)
  while read -r prefix url remote; do
    cur=$(ws_current_split "$prefix")
    [ "$remote" != "$cur" ] || continue
    ws_fetch_shallow "$url" "$remote" $cur
    changed="$changed$prefix $remote"$'\n'
  done <<< "$heads"
  while read -r prefix remote; do
    [ -n "$prefix" ] || continue
    if ! git subtree merge --prefix="$prefix" --squash "$remote" -m "ws: sync $prefix" >/dev/null 2>&1; then
      if [ -f "$(git rev-parse --git-path MERGE_HEAD)" ]; then
        die "conflito no sync de $prefix na $WS_BASE. Resolva (git status), faça commit, envie com git push origin $WS_BASE e rode $rotulo de novo"
      fi
      die "falha no sync de $prefix (git subtree merge); a $WS_BASE não foi alterada para esse repo"
    fi
    log "sincronizado $prefix"
  done <<< "$changed"
  ws_maintain_rejoin
}

# Envia a base com fast-forward. 0: enviada; 1: outra pessoa enviou antes (refazer). Para nas outras
# recusas. A resposta do origin fica em WS_SYNC_ERRO.
ws_sync_envia() {
  WS_SYNC_ERRO=$(git push -q origin "$WS_BASE:refs/heads/$WS_BASE" 2>&1) && return 0
  WS_SYNC_ERRO=$(printf '%s' "$WS_SYNC_ERRO" | tr -s '\r\n' ' ')
  case "$WS_SYNC_ERRO" in
    *TF402455*)
      die "push de $WS_BASE recusado por política do Azure DevOps (TF402455); a $WS_BASE não pode ter política de PR. Peça ao time do harness. Nada foi alterado no $WS_DESTINO." ;;
    *non-fast-forward*|*"fetch first"*)
      return 1 ;;
  esac
  die "push de $WS_BASE recusado. Resposta do origin: $WS_SYNC_ERRO"
}

# Lembrete do PR da base e aviso do destino local à frente do origin (sobra do ws start antigo).
ws_sync_avisos() {
  has_origin || return 0
  local n antiga idade max
  n=$(git rev-list --count "origin/$WS_DESTINO..$WS_BASE")
  if [ "$n" -gt 0 ]; then
    log "a $WS_BASE tem $n commit(s) que não estão no $WS_DESTINO; abra o PR, se ainda não estiver aberto: $(git remote get-url origin)/pullrequestcreate?sourceRef=$WS_BASE&targetRef=$WS_DESTINO"
    antiga=$(git log --format=%ct "origin/$WS_DESTINO..$WS_BASE" | tail -1)
    max=$(ws_atlas_cfg pr_max_dias)
    idade=$(( ($(date +%s) - antiga) / 86400 ))
    [ "$idade" -le "$max" ] \
      || log "aviso: a $WS_BASE tem sincronização de $idade dia(s) sem merge no $WS_DESTINO; peça a aprovação do PR"
  fi
  if git show-ref --verify -q "refs/heads/$WS_DESTINO"; then
    n=$(git rev-list --count "origin/$WS_DESTINO..$WS_DESTINO")
    [ "$n" -eq 0 ] \
      || log "aviso: seu $WS_DESTINO local tem $n commit(s) que não estão no origin; se forem só de sync (ws: sync, Squashed, Split), rode git switch $WS_DESTINO && git reset --hard origin/$WS_DESTINO"
  fi
}

# rotulo -> prepara, sincroniza e envia a base, refazendo sobre a ponta nova quando outra pessoa
# enviou antes. Termina na base.
ws_sync_base() {
  local rotulo=$1 tentativa
  for tentativa in $(seq 1 "$WS_SYNC_TENTATIVAS"); do
    ws_sync_prepara
    ws_require_added
    ws_sync_repos "$rotulo"
    has_origin || return 0
    ws_sync_envia && return 0
    [ "$tentativa" -lt "$WS_SYNC_TENTATIVAS" ] \
      || die "push de $WS_BASE recusado $WS_SYNC_TENTATIVAS vezes; rode o comando de novo. Resposta do origin: $WS_SYNC_ERRO"
    log "push de $WS_BASE recusado: outra pessoa enviou antes; refazendo sobre a ponta nova"
  done
}

# ws sync: sincroniza e envia a base e volta para a branch em que estava.
ws_sync() {
  cd "$(ws_root)"
  require_clean
  local volta
  volta=$(current_branch)
  ws_sync_base "ws sync"
  ws_sync_avisos
  [ "$volta" = "$WS_BASE" ] || git checkout -q "$volta"
}

# ws start <branch>: ws sync e a branch nova a partir da base.
ws_start() {
  local br=${1:-}
  [ -n "$br" ] || die "uso: ws start <branch>"
  git check-ref-format --branch "$br" >/dev/null 2>&1 || die "nome de branch inválido: $br"
  cd "$(ws_root)"
  require_clean
  if git show-ref --verify -q "refs/heads/$br"; then die "a branch $br já existe"; fi
```
