`tools/speckit/ws/scripts/bash/ws-bug-start.sh`:

```bash
#!/usr/bin/env bash
# Comando speckit.ws.bug-start da extensão ws, chamado pelo preset bugs no início do
# /speckit-bug-assess: cria a branch hotfix/<slug> com ws start (spec SP5, 4.3).
# - Slug: <id do work item>-<descrição> ou inc-<AAAAMMDD>-<descrição>, em minúsculas e com hífens.
# - Já na branch hotfix/<slug>: continua nela, sem ws start (assess repetido ou retomado).
# - Bug já registrado em bugs/<slug>/ no main, ou branch hotfix/<slug> no origin: erro.
# Uso: ws-bug-start.sh <slug>
# Saída: uma linha JSON com BRANCH_NAME, BUG_DIRECTORY, EXISTING e ERROR.
set -uo pipefail

WS_BASE=${WS_BASE:-main}

json_str() {
  local s=$1
  s=${s//\\/\\\\}
  s=${s//\"/\\\"}
  s=${s//$'\r'/}
  s=${s//$'\t'/ }
  s=${s//$'\n'/\\n}
  printf '"%s"' "$s"
}

# branch pasta existente erro
emit() {
  printf '{"BRANCH_NAME":%s,"BUG_DIRECTORY":%s,"EXISTING":%s,"ERROR":%s}\n' \
    "$(json_str "$1")" "$(json_str "$2")" "$3" "$(json_str "$4")"
}

fail() { emit "" "" false "$1"; exit 1; }

slug=${1:-}
[ -n "$slug" ] || fail "uso: ws-bug-start.sh <slug>"
[[ $slug =~ ^([0-9]+|inc-[0-9]{8})-[a-z0-9]+(-[a-z0-9]+)*$ ]] \
  || fail "slug inválido: $slug. Use <id do work item>-<descrição> ou inc-<AAAAMMDD>-<descrição>, em minúsculas e com hífens"
br="hotfix/$slug"
dir="bugs/$slug"

root=$(git rev-parse --show-toplevel 2>/dev/null) || fail "fora de um repo git"
cd "$root" || exit 1

if [ "$(git symbolic-ref --short -q HEAD)" = "$br" ]; then
  emit "$br" "$dir" true ""
  exit 0
fi

# O ws start cria a branch a partir do main do origin; a checagem olha o mesmo lugar.
base=$WS_BASE
if git remote get-url origin >/dev/null 2>&1; then
  git fetch -q origin "$WS_BASE" 2>/dev/null && base="origin/$WS_BASE"
  if git ls-remote --exit-code --heads origin "$br" >/dev/null 2>&1; then
    fail "a branch $br já existe no origin: faça checkout dela (git switch $br) para continuar o bug"
  fi
fi
if git cat-file -e "$base:$dir" 2>/dev/null; then
  fail "o bug $slug já está registrado no $WS_BASE ($dir/); para uma nova investigação, use o slug $slug-2"
fi

out=$(bash "${WS_BIN:-$root/tools/ws/ws}" start "$br" 2>&1) \
  || fail "$(printf '%s\n' "$out" | grep -v '^[[:space:]]*$' | tail -1 | sed 's/^ws: erro: //')"
emit "$br" "$dir" false ""
```

- [ ] **Step 4: Implementar `ws-bug-registro.sh`**

`tools/speckit/ws/scripts/bash/ws-bug-registro.sh`:

```bash
#!/usr/bin/env bash
# Comando speckit.ws.bug-sem-correcao da extensão ws: registra um diagnóstico sem correção de
# código. Faz commit só de bugs/ e envia a branch hotfix/<slug> ao origin do workspace, sem
# ws push, porque nenhum repo mudou (spec SP5, 4.3 e 5.2).
# Uso: ws-bug-registro.sh "<mensagem de commit>"  — a mensagem é obrigatória quando há mudanças.
set -uo pipefail

WS_BASE=${WS_BASE:-main}

log() { echo "ws: $*"; }
die() { echo "ws: erro: $*" >&2; exit 1; }

msg=${1:-}
root=$(git rev-parse --show-toplevel 2>/dev/null) || die "fora de um repo git"
cd "$root" || exit 1
branch=$(git symbolic-ref --short -q HEAD) || die "HEAD destacado; faça checkout da branch hotfix/<slug>"
case "$branch" in
  hotfix/*) ;;
  *) die "ws-bug-registro só roda numa branch hotfix/<slug> (atual: $branch)" ;;
esac

fora=$(git status --porcelain --untracked-files=all | cut -c4- | grep -v '^bugs/' || true)
[ -z "$fora" ] \
  || die "há mudanças fora de bugs/: $(printf '%s ' $fora). Um diagnóstico sem correção só registra o relatório; se houve correção de código, siga /speckit-bug-fix e /speckit-bug-test"

if [ -n "$(git status --porcelain --untracked-files=all -- bugs/)" ]; then
  [ -n "$msg" ] || die "informe a mensagem de commit"
  git add -A -- bugs/ || die "git add falhou"
  git commit -q -m "$msg" || die "git commit falhou"
  log "commit: $(git log -1 --format='%h %s')"
fi

git diff --quiet "$(git merge-base "$WS_BASE" HEAD)" HEAD -- bugs/ && die "nada a registrar em bugs/"

if git remote get-url origin >/dev/null 2>&1; then
  git push -q -u origin "$branch" || die "push da branch $branch recusado"
  log "branch $branch enviada ao origin; abra o PR do workspace para o $WS_BASE"
else
  log "sem origin: o commit ficou só local"
fi

## Comandos de bug e `hotfix/`

### O slug do bug é recusado

**Sintoma:**
```
slug inválido: <slug>. Use <id do work item>-<descrição> ou inc-<AAAAMMDD>-<descrição>, em minúsculas e com hífens
```
**Causa:** o nome do bug saiu fora da convenção, em geral com maiúscula ou acento vindos do título do work item.

```
**Causa:** já existe `bugs/<slug>/` no `main`, de uma investigação anterior do mesmo work item.

**O que fazer:** leia o relatório antigo. Se for uma investigação nova, rode o `/speckit-bug-assess` de novo com o slug sugerido.

**Sintoma:**

a branch <branch> já existe no origin: faça checkout dela (git switch <branch>) para continuar o bug
```

ws: erro: a branch <branch> já existe
```
**Causa:** alguém, talvez você, já começou esse bug.

**O que fazer:** rode `git switch hotfix/<slug>` e continue de onde parou: `/speckit-bug-fix` se o `assessment.md` já existe, ou `/speckit-bug-test` se o `fix.md` já existe. Os comandos acham o bug pela pasta.

**Sintoma:** o `/speckit-bug-fix` ou o `/speckit-bug-test` pergunta qual bug, ou diz que falta o `assessment.md`.

**Causa:** você não está na branch do bug, ou há mais de um bug em `bugs/` com o mesmo passo pendente.

**Sintoma:** o `test.md` registra `partial` (com checagens `not-run`) ou `failed`, e o agente não oferece o envio direto.

**Causa:** `failed` quer dizer que o sintoma continua; `partial`, que parte da verificação não pôde ser feita, por exemplo porque o repo não tem testes.

**O que fazer:** com `failed`, rode `/speckit-bug-fix` de novo (ou `/speckit-bug-assess`, se a causa mudou). Com `partial`, leia o motivo e decida se envia; o PR do repo é o lugar para o time conferir o que faltou.

### Não tenho acesso ao banco

**Sintoma:** o agente quer rodar um `SELECT` e a conexão falha, ou você não tem acesso àquele banco.

**Causa:** o harness não fornece credencial de banco; o agente só usa um acesso que você já tem.

**O que fazer:** diga que não tem acesso. O agente escreve a consulta, e você a roda com quem tem acesso e cola o resultado.

**Sintoma:**
```
ws: erro: há mudanças fora de bugs/: <arquivos>. Um diagnóstico sem correção só registra o relatório; se houve correção de código, siga /speckit-bug-fix e /speckit-bug-test
```
**Causa:** há arquivos alterados fora de `bugs/`, em geral em `repos/`.

**O que fazer:** se a mudança foi por engano, desfaça com `git restore <arquivo>` e registre de novo. Se houve correção de verdade, siga o fluxo com `/speckit-bug-fix` e `/speckit-bug-test`.
